# Опис маршрутів та інтерфейсів

Нижче наведено основні вебмаршрути Request Portal. Маршрути, що працюють із персональними або службовими даними, потребують автентифікації та перевірки ролі.

| HTTP-метод | URL-маршрут | Призначення | Роль, яка має доступ |
|---|---|---|---|
| **GET** | `/` | Перегляд каталогу активних послуг | Усі відвідувачі |
| **GET** | `/my/requests` | Перегляд списку власних звернень клієнта | Клієнт |
| **POST** | `/my/requests` | Створення нового звернення | Клієнт |
| **POST** | `/my/requests/{id}/cancel` | Скасування власного звернення | Клієнт; лише для статусу **Нова** |
| **GET** | `/manager/requests` | Перегляд усіх звернень і застосування фільтрів | Менеджер |
| **POST** | `/manager/requests/{id}/assign` | Призначення поточного менеджера відповідальним за звернення | Менеджер |
| **PATCH** | `/manager/requests/{id}/status` | Зміна статусу звернення | Менеджер |

## Додаткові правила інтерфейсу

- `{id}` — ідентифікатор звернення.
- Маршрути клієнта `/my/requests` доступні лише автентифікованим клієнтам.
- Маршрути `/manager/requests` доступні лише автентифікованим користувачам із роллю **Менеджер**.
- Для переходу до статусу **Відхилена** у запиті `PATCH` потрібно передати поле `rejection_reason`.
- Дозволені переходи статусів: **Нова → В роботі → Завершена**; на етапах **Нова** та **В роботі** також можливий перехід до **Відхилена**.
